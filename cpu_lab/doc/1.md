# Document 1 — Headers / includes

Both files start with `#include` because C++ does not automatically know about strings, files, directories, or OS APIs. An include **declares** names. The linker later **connects** them to real implementations in the C library, the C++ standard library, or the kernel.

There are three kinds in this project:

| Kind | Looks like | Who provides it |
|------|------------|-----------------|
| Your header | `"cpu_info.hpp"` | This project |
| C++ standard library | `<string>`, `<fstream>`, `<set>` | libstdc++ / libc++ |
| C / POSIX / OS | `<dirent.h>`, `<unistd.h>`, `<sys/sysctl.h>` | system C library + kernel |

Quotes `"..."` search your project first. Angle brackets `<...>` search the compiler’s system include paths.

`#if defined(__linux__)` / `#if defined(__APPLE__)` is not an include. The compiler defines those macros. Only one of the two `.cpp` files actually compiles `probe_cpu()` on a given machine, so you do not get two copies of the same function.

### `<sys/sysctl.h>` (Darwin / BSD)

**In this code:** `sysctlbyname(const char* name, void* oldp, size_t* oldlenp, void* newp, size_t newlen)`.

You only **read**:

- `oldp` / `oldlenp` = output buffer and its size
- `newp = nullptr`, `newlen = 0` = “do not write a new value”

Return `0` on success, `-1` on failure.

Two call patterns:

1. **Number:** pass `&v` and `sizeof(v)`.
2. **String:** first call with `oldp = nullptr` to learn the length, then allocate, then call again.

**In general:** `sysctl` is the BSD “ask the kernel a named question” API. Other keys you are **not** using yet:

- `hw.memsize` — RAM
- `hw.packages` — CPU sockets
- `hw.perflevel0.logicalcpu` / `hw.perflevel1.logicalcpu` — P-cores vs E-cores on Apple Silicon
- `kern.hostname`, `kern.osrelease`
- `sysctl` (MIB integer array) vs `sysctlbyname` (string name)

`::` in `::sysctlbyname` means “the function in the global namespace,” not a C++ class method. That avoids clashes if you ever add a function with the same name.

**In this code:** walk a directory without `std::filesystem`.

**In this code:** `std::set<std::pair<int, int>> cores` in `physical_core()`. Each unique `(package_id, core_id)` is inserted once. `cores.size()` is the physical core count.

**In general:** `std::set<T>` is an ordered unique collection (usually a tree).

Related:

- `std::unordered_set` — hash set, faster average, no order
- `std::map` / `unordered_map` — key → value
- `std::vector` — not unique unless you sort + unique yourself

# Document 2 — Functions in both probe files

Both files implement **one public function**: `CpuInfo probe_cpu()`. Everything else is a **private helper** inside an anonymous namespace (`namespace { ... }`). Those helpers have **internal linkage**: only this `.cpp` can see them. That is why both files can have different helpers with similar jobs and will not clash at link time.

```
probe_cpu()                          ← public, declared in cpu_info.hpp
    ├── read helpers                 ← talk to OS
    ├── parse helpers                ← turn text/bytes into numbers
    └── field fillers                ← write CpuInfo members
```

On a Mac, only the Apple helpers exist. On Linux, only the Linux helpers exist. Same return type, same meaning of each field.

## Part A — `cpu_info_macos.cpp`

### Why this file is short

macOS already aggregated topology into **named kernel variables**. You ask by string. You do not walk `/sys`.

---

### `read_i64(const char* key, std::int64_t& out) → bool`

**Role:** read one numeric sysctl into a 64-bit integer.

**Steps:**

1. Try `sysctlbyname` into an `int64_t`. If the kernel writes 8 bytes, success.
2. If that fails, retry into a 32-bit `int` (many `hw.*` keys are `int`).
3. Store the value in `out` and return `true`, or return `false`.

**Why `out` is a reference:** the function needs to return both “did it work?” and “what was the number?” Boolean + reference is the usual C++ pair for that.

**Why two widths:** `sysctlbyname` fails if your buffer size does not match the kernel’s idea of the key. Guessing 64 then 32 covers both.

**What it does *not* do:** it does not know about `CpuInfo`. It is a generic “read this key as an integer.”

---

### `read_str(const char* key) → std::string`

**Role:** read one string sysctl (`machdep.cpu.brand_string`, `hw.model`).

**Steps:**

1. Call `sysctlbyname(key, nullptr, &n, …)`. The kernel sets `n` to the needed byte count (including a trailing `'\0'`).
2. If that fails or `n == 0`, return empty.
3. Allocate `std::string s(n, '\0')` — `n` bytes of zeros.
4. Call again with `s.data()` so the kernel copies into that buffer.
5. `find('\0')` and `resize` so C++ does not keep the C terminator as part of the string.

**Why two calls:** you cannot know the brand-string length in advance. This is the standard “size query then read” pattern (same idea as asking a function for buffer length first).

---

### `probe_cpu() → CpuInfo` (macOS)

**Role:** the only function `main` will call. Fill every field.

| Field | How |
|--------|-----|
| `name` | brand string; if empty, `hw.model` (common on Apple Silicon) |
| `physical_core` | `hw.physicalcpu` |
| `logical_cpus` | `hw.logicalcpu` |
| `cache_line` | `hw.cachelinesize` |
| `l1d` / `l2` / `l3` | `hw.l1dcachesize` / `l2` / `l3` (bytes; L3 may stay 0) |

`static_cast<unsigned>(v)` / assigning into `std::size_t` fields converts the 64-bit scratch value into the struct’s types.

## Part B — `cpu_info_linux.cpp`

Linux does **not** give one `hw.physicalcpu` key. The kernel exports a **filesystem** (`/proc`, `/sys`). Helpers fall into four groups.

---

### Group 1 — text helpers

#### `trim(std::string s) → std::string`

**Role:** remove leading/trailing whitespace from a line.

Sysfs values often look like `"32K\n"` or `" Data "`. Comparing `" Data "` to `"Data"` would fail without trim.

It copies the string (pass by value), erases from the front while `isspace`, pops from the back while `isspace`, returns the cleaned copy.

**General idea:** a small string-normalization helper. You will reuse this kind of function anytime you parse text files.

*(Intended function is `std::isspace` and `unsigned char`, not `ispace` / `unsigned_char`.)*

---

#### `read_file(const std::string& path) → std::string`

**Role:** open a path, read the **first line**, trim it.

Almost every Linux hardware file is one line: `"3"`, `"32K"`, `"Data"`.

If `ifstream` fails (path missing), return `{}`. Callers treat empty as “this attribute does not exist.”

**General idea:** a tiny “read this kernel file as a string.” You could later extend it to read the whole file; you do not need that here.

---

### Group 2 — directory helpers

#### `is_numbered(const char* name, const char* prefix) → bool`

**Role:** is this directory name `prefix` + one or more digits?

Examples that must match: `cpu0`, `cpu12`, `node0`.  
Examples that must not: `cpufreq`, `cpu` (no digit), `.`, `..`, `present`.

Algorithm:

1. `strlen(prefix)`
2. `strncmp(name, prefix, n) == 0` — starts with the prefix
3. `name[n]` must be a digit (so `"cpu"` alone fails)
4. every remaining character must be a digit

**Why not `starts_with("cpu")` alone:** `cpufreq` would count as a CPU.

---

#### `count_numbered_dirs(const char* dir, const char* prefix) → unsigned`

**Role:** how many matching subdirectories?

Used twice:

- `("/sys/devices/system/cpu", "cpu")` → logical CPUs
- `("/sys/devices/system/node", "node")` → NUMA nodes

`opendir` / `readdir` / `closedir` is the loop. If the directory cannot be opened, return `0` (caller applies a fallback).

**General idea:** “count entries that look like `prefix + number`.” Same helper, two trees.

*(Intended call is `opendir`, not `opened`.)*

---

### Group 3 — parse / interpret

#### `parse_sysfs_size(const std::string& s) → std::size_t`

**Role:** turn sysfs cache size text into **bytes**, so Linux matches macOS (`hw.l1dcachesize` is already bytes).

| Input | Result |
|-------|--------|
| `"32K"` | `32 * 1024` |
| `"4096K"` | `4096 * 1024` |
| `"2M"` | `2 * 1024 * 1024` |
| `"64"` (no suffix) | `64` |

`strtod` parses the number and sets `end` to the first unparsed character. You inspect `*end` for `K`/`M`/`G`.

**Why not `atoi`:** `atoi("32K")` is `32` and **drops** the unit, so you would under-report by 1024.

---

#### `cpu_name() → std::string`

**Role:** human-readable CPU name from `/proc/cpuinfo`.

That file is many `key : value` lines, repeated per logical CPU. You want the first useful name:

1. Prefer `model name` (x86, many ARM boards).
2. Else remember `Hardware` (some ARM SoCs only have that).
3. Split each line at `:`, trim both sides.

You stop at the first `model name` so you do not walk every sibling CPU.

---

#### `physical_core() → unsigned`

**Role:** count **physical cores**, not threads.

For each `cpuN`:

- read `.../topology/physical_package_id` (which socket)
- read `.../topology/core_id` (which core on that socket)
- insert `(package, core)` into a `std::set`

Two logical CPUs on the same core (SMT) produce the same pair. The set keeps one. `size()` is the core count.

This is the Linux replacement for `hw.physicalcpu`.

---

#### `fill_caches(CpuInfo& info)`

**Role:** walk `cpu0`’s cache indices and write `cache_line`, `l1d`, `l2`, `l3`.

Linux exposes caches as:

```
/sys/devices/system/cpu/cpu0/cache/index0/
    level                 → 1, 2, or 3
    type                  → Data / Instruction / Unified
    size                  → 32K
    coherency_line_size   → 64
```

`index0` might be L1d, `index1` L1i, `index2` L2, and so on. You loop `index0` … `index15` and **stop** when `level` cannot be read (folder gone).

Intended assignment rules:

- first non-zero `coherency_line_size` → `info.cache_line`
- level 1 + type `Data` (or `Unified` if no Data yet) → `info.l1d`
- first level 2 → `info.l2`
- first level 3 → `info.l3`

You only look at **cpu0**. Cache *geometry* is the same for the package; sizes are what the brief asked for, not a per-core map.

`CpuInfo&` means “modify the caller’s struct,” not return a copy.

**Your current function reads these files but never writes `info`.** After you understand it, add those assignments or caches will stay 0.

---

### Group 4 — public entry

#### `probe_cpu() → CpuInfo` (Linux)

**Role:** same as macOS: assemble the struct.

| Field | How |
|--------|-----|
| `name` | `cpu_name()` |
| `logical_cpus` | count `cpuN`; if 0, `sysconf(_SC_NPROCESSORS_ONLN)` |
| `physical_core` | unique topology pairs |
| caches | `fill_caches` |
| `numa_nodes` | count `nodeN`; if 0, `1` (UMA / no NUMA sysfs) |

`if (info.logical_cpus = 0)` is an **assignment**, not a test. It would wipe the count and always take the `sysconf` path. It must be `==`.

## Side-by-side: same job, different OS

| Job | macOS helper | Linux helper |
|-----|----------------|--------------|
| Read a number from the OS | `read_i64` + `sysctlbyname` | `read_file` + `atoi` / `strtod` |
| Read a name | `read_str` | `cpu_name` parsing `/proc/cpuinfo` |
| Logical CPUs | key `hw.logicalcpu` | count `cpuN` or `sysconf` |
| Physical cores | key `hw.physicalcpu` | set of `(package, core)` |
| Cache sizes | keys `hw.l1dcachesize` … | `fill_caches` + `parse_sysfs_size` |
| Cache line | `hw.cachelinesize` | `coherency_line_size` |
| NUMA | write `1` | count `nodeN` |

That is the whole point of two `.cpp` files and one header: **`CpuInfo` is the portable model; the OS details stay in helpers.**
